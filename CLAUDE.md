# Metro Live Map — Developer Workflow

## Git Workflow Rules

These rules apply to **every Claude Code session**. They enforce safe, reviewable development.

1. **Never commit directly to `main`.** Always work on a feature branch. Claude Code creates a git worktree + branch automatically — use it.
2. **Commit after each logical sub-task** using the format `feat:`, `fix:`, `polish:`, or `refactor:` followed by a short description.
3. **Check `.gitignore` before staging.** Never track `.env`, `scripts/*.jsonl`, `*.log`, or GTFS `.txt` files.
4. **Scope control.** Only modify files directly relevant to the current task. If a change in another file is needed, flag it to the user before editing.
5. **All merges go through a Pull Request.** The user reviews each changed file in GitHub Desktop before approving. Do not ask to bypass this.
6. **No force pushes.** Never run `git push --force` or `git reset --hard` without explicit user approval.

## Key Constraints

- **No build step** — all imports are relative ES module paths. CDN libs loaded via `<script>` tags in `index.html`.
- **Always edit files in the active worktree**, not directly in the main branch if a worktree is open.
- **data/ files** — Built JSON files (rail-shapes.json, stops.json, trips.json, bus-routes.json, metro-micro-zones.json) are committed; raw GTFS source files (*.txt, *.zip) are gitignored.
- **GitHub Pages deployment** — serves from repo root. `index.html` must be at root. Push to `main` auto-deploys. Custom domain `livemap.metro.net` in CNAME is pending DNS.
- **API keys** in `config.js` are client-visible; restrict via referrer policies in ESRI/MapTiler dashboards.
- **Tests** — `npm test` runs the Vitest suite (~28 files, ~589 tests covering predictions, snap, heading, spike rejection, marker lifecycle, vehicle popup HTML rendering, error boundary, adherence, boarding merging, trip updates, the WS API, alerts ingestion + normalization, bus-bridge detection, build-shapes logic, freshness tiers, service-date rollover, accuracy aggregator + substitution-impact metric, pure utility math). Run after any change to ETA, snapping, or marker logic. Test environment uses a small in-memory localStorage shim in `tests/setup.js` (Node 25+ has a broken built-in `globalThis.localStorage` accessor that collides with jsdom).
- **Motion model — bounded arc-glide (PR #257, 2026-05-27)** — dead-reckoning was retired entirely. On every WS frame for a **rail** marker with shape data, `arcGlide(markerKey, fromArc, toArc, ...)` in `markers.js` glides the marker ALONG the polyline arc from its previous snapped position to the new snapped position. **Glide duration tracks the real inter-fix gap** (`(newTs - prevTs)*1000`, floored at `GLIDE_MIN_MS`, PR #269) so the marker's on-screen speed ≈ the vehicle's real average speed. A FIXED duration (the original 1 s, then 5 s) caused the "zooming across the whole line" bug: a long-gap advance rendered in a fixed short window = an absurd on-screen speed. **Re-anchor (teleport, no glide)** when the move can't be shown as plausible motion: straight-line jump > 5 km, stale reference (gap > `SPIKE_BYPASS_S`), gap > `GLIDE_MAX_MS` (30 s), or an arc jump whose implied speed exceeds `RAIL_MAX_SPEED_MPS × 1.5` (snap-arc ambiguity near looping track, or a spike the loose arc-gate let through). **Rotation** is a simple lerp from `startHeading` (prior `marker.properties.Heading`) to `targetHeading` (this frame's `computeHeading()` result — already disambiguated against the next-station bearing via `downstreamBearing`). The earlier per-frame polyline-tangent + arcSign rotation (PRs #260/#261) was retired in PR #262 because arcSign was fragile under snap wobble and the visual win over the glide was negligible. **Position bound between two known GPS positions** — cannot extrapolate, cannot overshoot, cannot disagree with the popup label. Critical invariant: the marker NEVER moves past the latest GPS fix. When the next WS frame arrives before the glide completes (typical case at 5 s), the in-flight glide is cancelled and a fresh glide starts from the marker's current visual position via `_currentArc` — smooth handoff, no jump. **Buses** (no shape data) use `animateMarker` straight-line lat/lng glide between WS frames at the same gap-matched duration (PR #263 converted animateMarker from step-count to wall-clock-time semantics so glide duration is independent of display refresh rate; PR #269 made the duration gap-proportional + added the bus re-anchor when implied straight-line speed exceeds `MAX_PLAUSIBLE_SPEED_MPS`). **Cold start** spawns the marker at its snapped GPS position with no glide. Vehicle motion (both arcGlide and animateMarker, position AND rotation) is intentionally **not** gated by `prefers-reduced-motion` — it represents real-world movement (functional, WCAG-2.3.3-exempt). Gating it (PRs #243/#257) caused the "markers teleport, no smoothness" regression for Reduce-Motion users and was reversed in PR #267. **Trade-offs accepted**: B/D tunnel markers freeze for 3-5 min during tunnel transit (no GPS underground to glide to); mid-car antenna at platforms shows the marker 25-40 m past the platform centroid (where GPS says it is). If rider feedback reveals tunnel freeze as a real UX problem, a narrow heavy-rail-only schedule-speed fallback (~100 LOC, scoped to `route_code ∈ {802, 805}` + `speed === 0` + `secs_since_last_fix > 30`) is the documented follow-up — bounded by next physical station so it never projects past a stop.
- **All DR-extrapolation mitigations retired (PR #257, 2026-05-27)** — the declared-stop clamp (PR #210, narrowed PR #212), STOPPED_AT misfire detection, stopIdLag observability counter, GPS-inferred next-stop override (`_effectiveNextStopId`), and the station-popup past-target guard were all built to compensate for DR extrapolation overshoots. With DR removed and the marker bounded between two known GPS positions, none of these mitigations are needed — they all came out in the same PR. Future contributors: do NOT re-introduce a `speedFactor`, a `_drCurrentArc`, or any code that projects the marker past its last GPS fix. The arc-glide design specifically rules out extrapolation.
- **Feed-data correctness gates (2026-05-26)** — three rider-facing accuracy fixes the triple-pass audit surfaced: (1) `js/api.js` `processAndUpdate` rejects frames timestamped further than `FUTURE_TS_GRACE_MS` (5 s) in the future — without the gate, a future timestamp passes `Number.isFinite()` and breaks every downstream `now - ts` age check (collapses to 0 = "fresh"), letting a phantom train's marker glide past where GPS truly puts it. Tracked via the new `futureTs` drop counter. (2) `js/tripUpdates.js` `processUpdate` early-returns when `trip.scheduleRelationship === 'CANCELED'` so canceled trips never populate `masterArrivalsData` — riders no longer see ETAs for trains that aren't running. (3) Inside the per-stop loop, `stu.scheduleRelationship === 'SKIPPED'` causes that single stop to be omitted while sibling stops on the same trip keep their pills — a skipped stop must never appear in the arrivals list. All three are silent in the rider UI; the only difference is the *absence* of obviously-wrong data.
- **vehicleNoArrivalMatch counter (2026-05-26)** — reverse of `ghostArrivals`. Fires in `getVehicleEtaSecs` when a live IN_TRANSIT_TO marker has a finite `stopId`, the trip_updates feed has predictions for OTHER vehicles at that stop, but none matches THIS vehicle's `vehicle_id` or `trip_id`. Sustained non-zero indicates trip_updates lost the prediction for an active vehicle and the popup will silently fall back to a schedule-based ETA. Episode-gated via `marker._noArrivalMatchRecorded`, cleared on stopId advance. STOPPED_AT excluded (boarding / misfire detectors own that window).
- **Scheduled feed-reliability audit (2026-05-26)** — `.github/workflows/feed-reliability.yml` runs `scripts/audit-feeds.js` against the live Metro WS feeds twice a week (Wed mid-day Pacific, Fri PM peak Pacific) and uploads the JSON report as a 30-day artifact. The per-field coverage table is also surfaced in `$GITHUB_STEP_SUMMARY` so reviewers see the top-line `nonNull` percentages on the run page without downloading. **This is the source of truth for "does Metro actually populate field X?"** — every future audit that proposes capturing an optional GTFS-RT field (`occupancyStatus`, `arrival.uncertainty`, `tripUpdate.delay`, `position.bearing`, etc.) must consult the latest report's `vehicleFields` / `stuFields` block before committing to the work. Decision rule: ≥30 % nonNull → wire it up; 5–30 % → document partial coverage; <5 % → skip. Manual fresh capture: Actions → feed-reliability → Run workflow (default 20 min, accepts `--duration` overrides). The CLI also runs locally: `node scripts/audit-feeds.js --duration=30m --out=/tmp/r.json`. **First-run findings (2026-05-26)**: `occupancyStatus` 0%, `arrival.uncertainty` 4% (and only the constant sentinel 300/301), `tripUpdate.delay` 0%, `position.bearing` 44% but dominated by 0°/180°/270° sentinels — all four "Tier A unused fields" identified in the prior spec-grounded audit are skip-worthy. `stopTimeUpdate.scheduleRelationship === 'SKIPPED'` fires at 6% rate (the just-shipped gate is doing real work). `trip.scheduleRelationship === 'CANCELED'` at 1.8% rate. `trip.startDate` 100%, `trip.startTime` 97% — both reliable, and confirm next-day tripIds appear in the feed mid-day (25% of trip_updates carry tomorrow's startDate hours before rollover).
- **Cross-midnight trip preservation (2026-05-26)** — `js/serviceDate.js` `_preserveActiveTrips(oldTrips, newTrips, markers)` is invoked from `_reloadGtfsData` in `main.js` during the midnight service-date rollover. For any tripId still referenced by an active vehicle marker that exists in the OLD `masterTripsData` but NOT in the freshly-fetched JSON, the old entry is merged into the new data before the swap. Owl trips that started yesterday and are still physically on the map at 00:01 keep their static context (terminus, stop sequence, `isLast` pill) until they actually terminate, instead of falling back to route-cache-only data immediately. Safety: the feed-reliability audit confirmed tripIds are NOT recycled across service dates (each day's trips have unique integer IDs in Metro's database), so preserving by tripId never silently masks a same-id-different-trip entry. Pure-function helper exported for testing; `tests/serviceDate.test.js` covers the active/inactive matrix, double-presence safety, null/missing tripIds, and the numeric-tripId String-cast defensive path.
- **Synthetic schedule-based vehicleIds filtered from `scanGhostArrivals` (2026-05-26)** — Metro's trip_updates feed publishes schedule-derived predictions for trips that haven't been assigned a live vehicle yet, using vehicleIds of the form `block_<N>_schedBasedVehicle`. The first feed-reliability audit captured 1,484 such entries in a 20-minute window. They are NOT divergence by design — the genuine-ghost signal was being swamped. `js/feedStats.js scanGhostArrivals` now skips any vehicleId ending in `_schedBasedVehicle` (suffix match for forward-compat with any future block-naming changes that keep the suffix convention).
- **`rebuild-gtfs.yml` issue-fallback (PR #217, 2026-05-26)** — the weekly Mon 09:00 UTC auto-rebuild silently failed for two weeks because `peter-evans/create-pull-request@v6` was being blocked (most likely the repo-level "Allow GitHub Actions to create and approve pull requests" setting is off; the action returns HTTP 403 and the workflow logs the error but no PR appears). Trip coverage drifted to 67% before the first `feed-reliability` audit caught it. The workflow now has an `if: failure() && steps.diff.outputs.changed == 'true'` fallback that files an issue under label `gtfs-rebuild-failure` (dedup'd by title) with a direct link to the failing run and manual-rebuild commands. The fallback was introduced AFTER the underlying drift had been fixed manually via PR #216; if the repo setting was the cause and is now enabled, the next Monday's run should produce a PR directly and neither the fallback nor manual intervention will be needed.
- **localStorage feedStats ring (2026-05-26)** — each `_report()` tick with activity appends one snapshot to `localStorage.feedStatsRing` (max `FEED_STATS_RING_MAX = 1440` entries = 24 h). Entry shape: `{ t: unixSec, feeds: { [shortName]: { rcv, acc, drops:{…}, cadence } }, markers: { …full _markerStats snapshot incl. zeros }, ghosts }`. Inspect from the console: `JSON.parse(localStorage.feedStatsRing)`. Helpers in `js/feedStats.js`: `readFeedStatsRing()`, `clearFeedStatsRing()`, `FEED_STATS_RING_KEY`. Quota / parse errors are swallowed — the ring is best-effort observability and never crashes the report tick. Silent intervals (no feed traffic, no marker counters, no ghosts) are skipped so the ring isn't padded with zero rows. The headless harness (`scripts/live-accuracy-headless.js`) clears the ring before the in-page accuracy harness starts, then at end-of-run reads it via `page.evaluate` and appends a single tagged row at the tail of the JSONL artifact (detect via `row.__kind === 'feedStatsRing'`); `summary.json.meta.feedStatsEntries` records the entry count.
- **ID String-cast at the feed boundary** — `js/api.js` String-casts every feed-derived ID (`vehicle_id`, `trip_id`, `stopId`, `route_code`) before placing them on `feature.properties`. Downstream code does strict-equality lookups (e.g. `arrivals.find(a => a.vehicleId === vehicle_id)`), and the trip_updates side (`tripUpdates.js:200-201`) also String-casts on its side — a number-vs-string mismatch would silently drop cross-feed matches. The most visible failure mode is the bus/rail dispatch: `isBusRoute(routeCode)` does `routeCode === '910'`; a numeric `910` would route the whole bus fleet through rail physics with no log. Whenever you add a new feed-derived ID, cast at the api.js boundary, not at every reader.
- **`_openVehiclePopups` counter & marker-remove contract** — `markers.js` tracks open vehicle popups in this counter (incremented in `popup.on('open')`, decremented in `popup.on('close')`) so the two per-second `setVisibleInterval` ticks for popup-age refresh can short-circuit on `=== 0`. **MapLibre's `marker.remove()` does not reliably fire 'close' on an open popup**, so every call site that removes a marker MUST call `marker.getPopup()?.remove()` first — without it the counter drifts upward across multi-hour sessions and the refresh ticks run perpetually. The glide helpers (`arcGlide` for rail, `animateMarker` for buses) use a callback pattern (`marker._animateMarkerOnComplete`), not returned Promises — cancellation in `updateExistingMarker` deletes the flag so a cancelled glide cannot fire `updateMarkerTimestamp(marker, OLD_vehicle)` after the new GPS has already been applied.
- **Vehicle freshness tiers** — `getFreshnessTier(marker, nowSec)` in `js/freshness.js` (shared by `markers.js` and `ui.js`) is the single source of truth for per-vehicle VISUAL state. Three tiers map to (marker opacity, popup-dot color):
  - `live`    (age < 90 s)  → 1.0  / green
  - `stale`   (age < 300 s) → 0.5  / gray
  - `expired` (age ≥ 300 s) → fade-out & remove
  Constants: `FRESH_STALE_S` (90 s), `FRESH_EXPIRE_S` (300 s), `FRESH_CHECK_INTERVAL_MS`. Decoupled from `SPIKE_BYPASS_S` (120 s, spike-rejection) and `VEHICLE_MARKER_TTL_S` (180 s, ETA filter) — those are algorithmic gates, not visual. (A separate `FRESH_LIVE_S = 30 s` constant lives in config.js for predictions.js's speed-freshness gate — "is the smoothedSpeed reading still trustworthy?" — unrelated to the tier model.) The four-tier model with an intermediate `aging` band was retired in the KISS pass (2026-05-27); it had no behavioral consumers and the popup dot already rendered it as green.
- **Translation** — page source is English; the app declares `<html lang="en">` and relies on each browser's built-in translate feature (Chrome / Edge / Safari menu, iOS Safari AA menu, Android Chrome menu). The previous in-app en/es dictionary (`js/i18n.js`, `i18n/{en,es}.json`) was retired because (1) it only covered two languages, (2) it couldn't translate the LACMTA alerts feed (English-only with no `translations` field), and (3) browser-native translation handles ~100 languages AND translates alert prose alongside the rest of the page. Alert bodies are still wrapped `<p lang="en">` so screen readers and browser translators identify the source language explicitly; that wrapper is the only translation-related code remaining. (An earlier "globe" discovery button in `map.js` `CustomControls.translateBtn` was removed too — there's no JS API to trigger native translation, so the button was guesswork on top of guesswork.)
- **Global error boundary (PR #237, 2026-05-27)** — `js/errorBoundary.js` installs `window.onerror` + `window.addEventListener('unhandledrejection')` listeners at the very top of `main.js`. Every event increments a counter in feedStats (`globalErrors`, `unhandledRejections`) so the rate is visible in the localStorage ring buffer and the offline analyzer. When 3+ errors fire within a 30 s window, a dismissable recovery banner appears asking the rider to refresh — one-shot per session, repeated bursts don't stack banners. `installErrorBoundary()` is idempotent via a `window._errorBoundaryInstalled` flag. The boundary is the layer that prevents a single uncaught exception from leaving the map silently frozen with no rider-visible signal.
- **Non-text contrast for low-luminance route colors (PR #238, 2026-05-27)** — E (#fdb913 ~1.5:1), K (#e56db1 ~2.8:1), J (#adb8bf ~2.2:1) fail WCAG 1.4.11 (3:1 graphical-element non-text contrast) on white. Brand palette is preserved; structural mitigation: `.bar-fill` gets a 1 px inset dark outline + opacity 1.0 (was 0.85) so the colored fill has a visible edge against the white track. `.boarding-badge` in dark mode gets a 2 px border + inset light outline so the route-color border (`--bb-color`) is visible against the dark glass. `.pv2-dot` (vehicle popup freshness indicator) now carries `role="img"` + `aria-label="Data fresh|stale|expired"` — was color-only with no text alternative. `tests/route-color-contrast.test.js` pins the contrast of every route hex on white with drift detection on the known-failing entries — re-tune a color lighter than today and the test fails.
- **Focus trap + skip-link target (PR #239, 2026-05-27)** — alerts panel modal traps Tab/Shift+Tab at panel boundaries (WCAG 2.4.3); document-level keydown handler gated on `isAlertsPanelOpen()` so zero effect when closed. Mid-chain Tab passes through; only boundary cases preventDefault. `openAlertsPanel` snapshots `document.activeElement` before moving focus; `closeAlertsPanel` restores it (graceful fallback if the opener was detached). Skip-link in index.html now points at `#station-search` (a focusable interactive element), not the bare `#map` container which gave screen-reader users no keyboard path forward.
- **No client analytics (PR #240, 2026-05-27)** — GTM and GA4 were removed entirely along with their CSP allowlist entries and the `<noscript>` iframe fallback. No consent banner exists; collecting visitor IP without consent created a GDPR gap for EU riders for marginal Metro-side value. Removed rather than build a consent flow (KISS). CSP also gained `frame-ancestors 'self'` to prevent iframe-embed → invisible-overlay attacks. Re-introducing analytics requires a proper consent flow AND re-adding `https://www.googletagmanager.com` + `https://www.google-analytics.com` to the appropriate CSP directives — documented in the CSP comment in `index.html`.
- **A11y landmarks + ARIA wiring (PR #242, 2026-05-27)** — `<main id="map">` wraps the map (was a bare `<div role="region">`). `<header id="search-bar-wrap" role="search">` wraps the search bar (WAI-ARIA search landmark). Search input carries `aria-describedby="station-search-hint"` (visually-hidden keyboard hint announced on focus), `aria-controls="search-results"`, and `aria-expanded` for the listbox. `#alerts-tab-announce` is a polite live-region that `switchAlertsTab` writes "Service alerts tab selected" / "Accessibility alerts tab selected" to (most screen readers don't announce `aria-selected` changes on programmatic focus moves within a tablist; the explicit announcement carries the change). Station popup name is `<h3>` (was `<div>`) so heading-navigation works into popups.
- **`prefers-reduced-motion` does NOT gate the vehicle glide (PR #267, reverses #243/#257)** — `arcGlide` (rail) and `animateMarker` (buses) interpolate the marker between consecutive GPS fixes regardless of the user's reduced-motion setting. This is the vehicle MOTION MODEL — it conveys a real train moving along its track, which WCAG 2.3.3 explicitly exempts ("motion essential to the information being conveyed"). PRs #243/#257 mistakenly gated it, which turned every vehicle into a frame-to-frame teleport for the large population running OS-level "Reduce Motion" (default-on in many macOS/iOS accessibility setups) — the exact "markers just teleport, no smoothness" regression riders reported after the DR→glide refactor. The pre-#257 DR integrator was never gated, for the same reason. Decorative TRANSITIONS that are NOT essential information (map `flyTo`, popup fades, etc.) may still honor reduced-motion; vehicle position interpolation is not in that category.
- **Startup auto-locate popup gated on map idle + loading splash removal (PRs #266/#268)** — `autoLocate(isStartup=true)` opens the nearest-station popup after geolocation. It must wait for BOTH `map.once('idle')` (tiles rasterized, flyTo finished) AND the `loadingDone` promise exported from `ui.js` (resolved by `removeLoadingScreen`, which is gated on the 2nd WS connect in `api.js` or a 15 s fallback). Gating on only one let the popup render over the still-visible loading splash ("Expo / La Brea — No upcoming arrivals" floating on the loader). The locate-BUTTON path (`isStartup=false`) skips the splash gate — the splash is long gone by then.
- **ETA-source debug tag (`mlm_debug_eta`, PR #268)** — set `localStorage.mlm_debug_eta = '1'` (then reopen a vehicle popup) to render a small `[RT]` / `[calc]` tag next to the next-stop ETA, showing whether it came from a GTFS-RT trip_updates match or the schedule/distance calc fallback. `getVehicleEtaSecs` records the tier on `marker._etaSource` ('gtfs-rt' | 'calc' | 'stopped' | 'none'); `getPopupHTML` renders it only when the flag is set. Off by default, zero rider-facing effect. Built to diagnose "train is right there but says 3m" reports — usually a real queued wait behind a train occupying the platform, not a bad prediction.
- **Rollback runbook (PR #247, 2026-05-27)** — `docs/ROLLBACK.md` is the canonical recovery doc for "main is broken in production". Severity triage; §A immediate revert via `git revert` + `gh pr merge --admin` (no force-push, rule-6 compliant); §B fix-forward; §C restore from a known-good SHA (gated on explicit user approval). ## Cross-Module Globals (`window.*`)

The app deliberately exposes shared state on `window` instead of routing every read through explicit imports. This is a conscious choice for a no-build SPA — it keeps modules small and avoids circular-import gymnastics. Treat these as the public API surface between modules; **do not refactor them away without a plan.**

| Global                                       | Owner module           | Shape                                  |
|----------------------------------------------|------------------------|----------------------------------------|
| `window.map`                                 | map.js                 | MapLibre map instance                  |
| `window.masterStopsData`                     | main.js (loads)        | Object<stopId, {lat,lon,name,…}>       |
| `window.masterTripsData`                     | main.js (loads)        | Object<tripId, {…}>                    |
| `window.masterBusRoutes`                     | main.js (loads)        | Object<routeId, {…}>                   |
| `window.masterArrivalsData`                  | tripUpdates.js         | Map<stopId, Arrival[]>                 |
| `window.masterAlertsData`                    | alerts.js              | Map<routeCode, Alert[]>                |
| `window.masterStopAlertsData`                | alerts.js              | Map<stopId, Alert[]>                   |
| `window.masterStopAccessibilityAlertsData`   | alerts.js              | Map<stopId, AccessibilityAlert[]>      |
| `window.masterBikeStations`                  | bikeshare.js           | Map<stationId, {…}>                    |
| `window.vehicleMarkers`                      | markers.js             | Object<tripId, MapLibre marker>        |
| `window.stationGroups`                       | stations.js            | Array<MergedGroup>                     |

`tripTerminusByTripId` used to live on `window` too; PR #151 removed the
mirror — production consumers (`stations.js`, `predictions.js`) now import
the named binding from `tripUpdates.js` directly. The single-access-path
invariant prevents future writers from leaving one site reading stale state.

**Debug-only hooks** (not part of the contract — present for console inspection, fine to omit when refactoring):
- `window.__visRegistrySize` — exposed by `utils.js` for inspecting the `setVisibleInterval` registry size

### Cross-module callbacks (`window.__`)

In addition to the data globals above, `stations.js` exposes three function hooks on `window` so other modules can drive station-popup behavior **without importing `stations.js`** (which would create an init-order cycle through `main.js`). All three are set once at module load:

| Hook                                | Set by      | Called by      | Purpose                                                          |
|-------------------------------------|-------------|----------------|------------------------------------------------------------------|
| `window.__openStationByGroup`       | stations.js | bikeshare.js   | Open the station arrivals popup for a merged stop group          |
| `window.__hoverStationByGroup`      | stations.js | bikeshare.js   | Soft-preview hover (no pin) used when the user hovers a bike pin |
| `window.__closeStationIfUnpinned`   | stations.js | bikeshare.js   | Dismiss an unpinned hover-preview when the user leaves the pin   |

These are intentional inversion-of-control hooks — keep the `__` prefix and the optional-chained `?.()` call pattern so they fail silently if `stations.js` hasn't initialized yet.
